# OW Overwatch Commander

> 阵亡等待重生的那 5~15 秒里，回看你刚才那一波，告诉你最该改的地方。

一个跑在 Windows 上的 FPS「阵亡间隙即时复盘」工具。按一下键，约 3 秒后，屏幕右下角浮出一张卡片，**同时开口把结论念出来**，写着（说着）刚才那一波你错在哪。

---

## ⚠️ 先说清楚两件事

**一、它不碰游戏进程。** 抓画面用的是 Windows 桌面复制（和 OBS 同一套机制），浮层是一个普通置顶窗口——游戏全程不知道它存在。**不做**、也不会做注入游戏进程、读取游戏内存、自动瞄准这类事。

**二、别用在竞技排位里。** 联机竞技里任何形式的实时 AI 辅助都属违规，不限于自动瞄准。请只在单人、休闲或自定义房间使用。

---

## 技术栈

| 层 | 用的东西 | 为什么是它 |
|---|---|---|
| 抓画面 | **dxcam**（DXGI 桌面复制） | 不碰游戏进程；实测 13~19 ms/帧，我们要的只是 3 FPS，富余十倍 |
| 后台缓存 | 内存环形缓冲，存 JPEG 字节 | 90 帧只占约 6 MB，不拖游戏；存字节而非像素，落盘时不用再编码 |
| 触发 | **GetAsyncKeyState 轮询** | 不装系统全局钩子（在受限办公机上实测装了也不触发；且钩子对反作弊更显眼） |
| 抽帧 | **Pillow** + `frames.txt` 时间戳 | 从最后 10 秒里均匀抽 8 帧，兼顾时序和成本 |
| 视觉理解 | 阿里云百炼 **qwen3-vl-plus** | 多图 + 流式；首字约 1~2 秒，单次约 0.6 分钱 |
| 语音播报 | 百炼 **qwen3-tts-flash** / **cosyvoice-v3.5-flash**（dashscope 原生接口） | 实时流式合成 + 边收边播；出声约 1 秒。前者四个现成音色，后者能用你自己的声音，而且**语速可调** |
| 语音播放 | PySide6 **QtMultimedia**（QAudioSink） | 界面已经有 Qt 了，不再引入 pyaudio 之类的依赖 |
| 界面 | **PySide6 6.12（Qt 6）** | 置顶 / 逐像素透明 / 鼠标穿透都是原生支持，卡片本体可做半透明玻璃质感 |
| 色彩处理 | **opencv-python** | dxcam 的硬依赖，缺了会静默降级到慢速后端 |
| 运行时 | Python 3.10+（项目内 `.venv`） | 依赖隔离，不污染系统 Python；路径不写死任何机器 |

**为什么界面不用 pywebview**：实测它在 Windows 上的透明是半成品——源码里没实现窗体级透明，透明模式下窗口还会藏着不显示。Qt 的逐像素 alpha 是真透明，卡片本身能半透明，圆角也没有黑边。

## 怎么工作的

```
游戏在前面跑
   ↓  后台一直在存（3 FPS，只留最近 30 秒，滚动覆盖）
你阵亡了，按一下键
   ↓  再把按键之后 2 秒也抓进来
落盘成一组 JPEG（约 0.7 秒）
   ↓  取最后 10 秒，均匀抽 8 帧
发给视觉模型（流式）
   ↓  想到一个字就回一个字
右下角浮出卡片，一个字一个字蹦出来
   ↓  文字同时喂给语音合成（攒够一句就开念）
耳朵听到结论（约 3.5 秒出声，念完约 6 秒）
   ↓  语音播完后卡片再淡出
自动淡出
```

**为什么必须"一直存"**：你死的那一刻，正是战斗画面已经没了的那一刻。死了再截图只会拿到死亡黑屏。所以缓存是地基，不是截图。

**为什么语音也要流式**：实测 23 个字的结论，音频长 4.4 秒，全部合成完只要 1.3 秒——合成速度是播放速度的 3.3 倍。所以收到第一块就开播，0.5 秒出声，后面永远有货。等整段合成完再播就是白白多等一秒。

## 安装

需要 **Windows** + **Python 3.10 以上**（本项目在 3.13 上跑通）。下面所有命令都在**项目文件夹里**执行。

**0. 拿到代码**

```bat
git clone https://github.com/gujianlaogong/OW-overwatch-commander.git
cd OW-overwatch-commander
```

（下载 zip 解压也一样，进到那个文件夹就行。）

**1. 建一个虚拟环境，把依赖装进去**

CMD / PowerShell：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Git Bash 这类 shell（斜杠反过来）：

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
```

> - `python` 命令不存在？去 [python.org](https://www.python.org/downloads/) 装（记得勾 "Add python.exe to PATH"），或者把命令里的 `python` 换成 `py -3`。
> - 依赖装在项目自己的 `.venv` 里，**不污染系统 Python**。装完之后，这个项目用的永远是 `.venv` 里那个解释器。
> - `.venv` 已经在 `.gitignore` 里，不会进仓库，所以每个人都在自己机器上建一次。
> - **`opencv-python` 不是可选的**：dxcam 拿它做色彩转换，缺了会静默降级到 mss 后端，单帧从约 13 ms 掉到约 40 ms，全屏独占下也更容易抓到黑屏。装没装对不用靠猜，下一步的 `check.py` 会直接告诉你实际用上的是哪个后端。

**2. 填 API Key**

去 [阿里云百炼控制台](https://bailian.console.aliyun.com/) 建一个 Key，粘进 `key.txt`（一行，不要引号、不要空格）。**这个文件已在 `.gitignore` 里，不会进仓库。**

**3. 游戏设置**

把游戏显示模式改成 **无边框窗口**（有的游戏叫"窗口化全屏"）。独占全屏很可能抓到纯黑画面，这一点是必须的。

## 使用

### 装完先自检

```bat
.venv\Scripts\python.exe check.py
```

三秒钟打一张表：哪样装了、哪样没装、没装的话该敲什么。**全绿**就可以往下走了。

```bat
.venv\Scripts\python.exe check.py --online   :: 顺带验证 API Key 通不通（免费，不调模型）
```

> 最值得看的一行是 **抓帧后端**：必须是 `dxcam`。
> 如果显示 `mss`，说明 `opencv-python` 没装上——dxcam 缺了它会悄悄降级，不报错、只是变慢。

### 最省事：双击 `run.bat`

它会自动切到正确目录、找到 `.venv` 里的 Python 启动。没建虚拟环境的话它会提示你该敲哪两行，不会闷头报错。

### 命令行

CMD / PowerShell：

```bat
.venv\Scripts\python.exe coach.py --analyze
```

Git Bash：

```bash
./.venv/Scripts/python.exe coach.py --analyze
```

> 后面所有命令都省掉了前面的 `.venv\Scripts\python.exe`，写全就是
> `.venv\Scripts\python.exe analyze.py --dir ...` 这样。
> 如果你已经激活了虚拟环境（`.venv\Scripts\activate`），直接写 `python coach.py --analyze` 也行。

然后：

1. 开游戏（无边框窗口模式）
2. **先在桌面按一次 F8**，确认控制台有反应
3. 进游戏，**阵亡后按 F8** → 约 3 秒后右下角出结论

### 常用参数

| 参数 | 作用 |
|---|---|
| `--analyze` | 落盘后自动出复盘（不加就只落盘） |
| `--key xbutton1` | 换触发键。**推荐鼠标侧键**，FPS 里不抢键位（`xbutton1`/`xbutton2`） |
| `--post 0` | 按键立刻落盘，不抓死后那 2 秒 |
| `--fps 3 --seconds 30` | 缓存采样率与时长 |
| `--no-voice` | 不念出来，只看卡片 |
| `--voice Ethan` | 换音色。预置的：Cherry / Serena / Ethan / Chelsie；克隆的：一长串 ID（见下节） |
| `--rate 1.3` | 语速。**只对克隆音色有效**，1.0 偏慢，1.4 开始有点赶 |
| `--max-tokens 60` | 结论最长多少字。**接了语音之后这是硬约束**：每字约 0.18 秒音频，60 字就要念 10 秒以上，重生前听不完 |

### 让教练用你自己的声音念

预置音色是四个固定的公家声音。想换成**你自己的声音**（或者任何人的），用 `voice_clone.py` 克隆一个：

```bat
.venv\Scripts\python.exe voice_clone.py --list
.venv\Scripts\python.exe voice_clone.py --enroll 我的录音.mp3
.venv\Scripts\python.exe voice_clone.py --try  <上面吐出来的那串音色 ID>
```

第一步列已有的音色，第二步拿一段录音去登记、换回一个音色 ID，第三步戴着耳机听一下像不像。

**录音怎么录**：用系统自带的录音机就行，念一段 10~20 秒的日常说话，安静环境、别带背景音乐。手机录的也可以，拷过来直接用——**不用传到网上**，`voice_clone.py` 会把本地文件编成 Base64 直传给接口。

确认效果满意之后，把那串音色 ID 写进 `voice.txt`（一行，不带引号）。写完之后双击 `run.bat`，就是自己的声音在念，不用每次带参数：

```bat
echo cosyvoice-v3.5-flash-me-xxxxxxxxxxxx > voice.txt
```

这条路上有三件事跟预置音色不一样，踩过：

- **克隆音色只能配它自己的模型**。音色 ID 自带模型名前缀（`cosyvoice-v3.5-flash-me-xxxx`），代码会照着前缀反推该用哪个模型，不用自己操心。走 `--voice Cherry` 则还是原来的模型。
- **语音可以单独配 Key**。给克隆功能专门开了个 Key 的话，放进 `key_tts.txt`，没有就跟视觉模型共用 `key.txt`。
- **语速这回是真管用的**。之前那个模型的 `speed` 参数设 1.2 和 1.0 出来一样长，是摆设；克隆模型实测 1.0→1.6 音频从 6.6 秒压到 4.1 秒，是真的在压缩时长。

只分析已有的一组帧（不抓屏）：

```bat
.venv\Scripts\python.exe analyze.py --dir captures\<那次落盘的目录名>
.venv\Scripts\python.exe analyze.py --no-overlay     :: 不要浮层，纯控制台输出
```

## 实测数据（本机，Windows 11 / i5-14500 / Intel 核显）

| 项目 | 实测 |
|---|---|
| 单帧抓取 + 压缩 | 13~19 ms |
| 缓存吃满 90 帧 | 约 6.1 MB |
| 按键 → 落盘 30 帧 | 67~717 ms |
| 模型首字 / 说完 | 约 1.0~2.0 s / 2.0~2.7 s |
| 按键 → 出声 | 约 3.5 秒（分析 2.7 秒 + 合成首块 1 秒） |
| 按键 → 念完 | 约 6 秒（15 字结论） |
| 语音合成速度 | 是播放速度的 3.3 倍，边收边播不卡 |
| 克隆音色 22 字（语速 1.0 → 1.6） | 音频 6.6 s → 4.1 s，首块都在 0.6 s 左右 |
| 单次成本 | 视觉约 0.6 分钱 + 语音约 0.2~0.5 分钱 |

阵亡等待通常有十几秒，从按键到听完约 6 秒，正好赶在重生前。成本这一项基本可以从考虑清单里划掉。

## 目录结构

```
coach.py          主程序：后台缓存 + 热键 + 落盘
check.py          装完体检：哪样装了、哪样没装、没装该敲什么
analyze.py        分析：抽帧 → 调视觉模型 → 出结论
overlay.py        浮层卡片（Qt）
tts.py            语音层：流式合成 + 边收边播（单独试听：python tts.py "文字"）
voice_clone.py    声音克隆：拿一段录音换一个音色 ID
layout.txt        ★ 界面布局说明，按你玩的游戏自己改
requirements.txt  依赖清单（pip install -r 用）
run.bat           双击启动（自动找 .venv，不含任何机器专属路径）
key.txt           API Key，自己建，不进仓库
key_tts.txt       给语音单独配的 Key（可选，没有就跟上面共用）
voice.txt         默认音色，把克隆出来的 ID 写进去就不用每次带参数
cap_probe.py      抓帧自检（含黑屏检测）
qt_probe.py       浮层三要素自检（置顶/透明/穿透）
```

单独试听某个音色：

```bat
.venv\Scripts\python.exe tts.py "这句话念出来听听" --voice Ethan
.venv\Scripts\python.exe tts.py "这句话念出来听听" --voice cosyvoice-v3.5-flash-me-xxxxxxxx --rate 1.4
```

### `layout.txt` 是整个项目里最值钱的文件

它告诉模型"屏幕左上角是血条、右上是小地图、底部中间是弹药"。实测对比：

- **不给**：它会把左上角小地图误读成"你暴露的区域"，每次说法还不一样
- **给了**：幻觉消失，而且**首字延迟从 1.85 秒降到 1.0 秒**，还能准确追踪数字变化（"弹药从 30 降到 9 没换弹"）

换游戏就改这个文件。

## 已知限制

这些是真实的现状，不是客套：

1. **全屏独占会抓到黑屏**，必须改成无边框窗口。
2. **触发是手动的**。自动检测死亡没做——三个游戏的死亡画面长得完全不一样，误判会烦死人。先手动，跑通再说。
3. **按晚了会让分析失焦**。缓存一直在存，所以不会丢画面；但分析固定取"最后 10 秒"，如果你死了 10 秒才按，那 10 秒全是死亡画面。养成一死就按的习惯，或用 `--post 0`。
4. **结论必须短**。接了语音后这是硬约束：中文每字约 0.18 秒音频，默认 `--max-tokens 60` + 提示词里限 30 字，就是为了让它在重生前念得完。`speed` 加速参数在 qwen3-tts-flash 上实测无效。
5. **预置音色只有四个**（Cherry/Serena/Ethan/Chelsie），而且走的那条链路语速调不了。想用自己的声音或调语速，按上面那节克隆一个。
6. **需要联网**调 API（视觉和语音都是云端）。
7. **只支持 Windows**（抓帧、浮层、音频都依赖 Win32 / DXGI / WASAPI）。

## 路线图

- 卡片可拖动、可调透明度

## 一句话原理

它不做实时支招——联机 FPS 里 1.8 秒的延迟等于无用，而且越界。它做的是**即时复盘**：在你本来就要等着重生的那十几秒里，把上一波讲清楚，下一回合立刻能用。
